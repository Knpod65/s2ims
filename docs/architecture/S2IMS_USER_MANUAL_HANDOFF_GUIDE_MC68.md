# S2IMS User Manual Handoff Guide MC68

## Purpose
This guide explains how to use, review, and later export the role-based manual package.

## How to use the manual
- Start with the system status and safety boundary sections.
- Use the route inventory to verify that a page exists before referencing it.
- Use the role journey map for the page-by-page walkthrough order.
- Use the screenshot plan or pending index to understand evidence status.

## How to update screenshots
- Replace pending entries only after capturing safe local screenshots.
- Keep file names aligned with the naming convention in the screenshot plan.
- Store screenshots only in `docs/screenshots/mc68-role-based-user-manual/`.
- Update the evidence index if screenshots are captured later.

## How to export to Word/PDF later
- Treat the markdown package as the source of truth.
- Export only after the manual, route inventory, journey map, and screenshot status have been reviewed together.
- Preserve the safety notes and blocked-feature language in the exported version.

## What must be reviewed before distribution
- Role coverage completeness.
- Route inventory accuracy.
- Screenshot status accuracy.
- Safety boundary language.
- Privacy / PDPA wording.
- Any references to preview-only or demo-only content.

## Role owner review checklist
- Admin owner confirms admin routes and safety notes.
- Scholarship staff owner confirms staff routes and usage notes.
- Provider owner confirms provider routes and privacy boundaries.
- Student owner confirms student journey wording.
- ESQ / reviewer owner confirms review language does not imply approval.

## PDPA / privacy review checklist
- No real person identifiers in screenshots.
- No real student or staff records in the examples.
- No official evidence language.
- No export or persistence language that implies production usage.
- No screenshots of pages that expose sensitive records without the correct safe boundary.

## Versioning recommendation
- Keep the MC68 version identifier in the filename and document header.
- If screenshots are later captured, update the evidence index and record the capture date in the daily report.
- If routes change later, create a new revision rather than silently editing the current manual.

## Future MC69 recommendation
- Use MC69 only after the manual and screenshot set have been reviewed and, if needed, exported.
- MC69 should not reopen the runtime surface; it should focus on documentation packaging or later handoff if a new need appears.
